# Relay admission with independent ACK debt

The plugin derives static source/function shares from the complete topology
route set, including every destination, lane, channel and communicator. This
is a capacity model under the assumptions below, not physical qualification.

## Allocation

Let B be the effective base budget, at most 327680. Let U(q) contain each
source/function whose routes traverse queue q. The weight w(a) is the sum of
relay hops over source/function a's routes. The base allowance is
`W0(a) = min_q floor64(B*w(a)/sum(w(b), b in U(q)))`. Therefore the sum of
W0 over each queue's sources is at most B. `net_sircl_plan.c` reconstructs
forward and reverse lanes independently and requires reciprocal paths.

For reconstructable routes on 2-8 hosts, if every W0 is at least 1280, assign:

```
W(a) = floor64(6*W0(a)/5)       forward charged bytes
A(a) = floor128(W0(a)/5)       outstanding ACK bytes
```

Rounding only lowers each allowance. Every source can reserve a two-packet
control pair (256 ACK bytes). If any base share is smaller, retain W0 and the
scalar ACK bound for the whole topology. Unknown reconstruction, aliased
function names and more than eight hosts retain the aggregate
`floor64(B/max(1,N-2))` model. Invalid topology still fails closed.

For each nonempty write of payload L, negotiated verbs MTU M:

```
C(L,M) = 64*ceil(L/64) + 256*ceil(L/M)
ACK(L,M) <= 128*ceil(L/M)
```

The original conservative forward charge is unchanged, including its ACK
padding. The ACK ledger independently limits generated reverse traffic.
Both resources must fit atomically under the shared-window mutex before
posting. CTS and final pairs reserve 640 forward and 256 ACK bytes. Data
pieces shrink to fit both remaining balances. Only successful RC completion
releases reservations; failed/abandoned outstanding work poisons the pool.

For queue q, including ACKs generated by the opposite direction:

```
occupancy(q) <= sum(W(a), a in U(q)) + sum(A(b), b in U(reverse(q)))
             <= 6B/5 + B/5 <= 458752 bytes
```

The aggregate fallback uses `ACK <= 2C/5` and obeys the same 7B/5 envelope.
With 512 KiB independent queues the model leaves 65536 bytes of margin.
On a four-host path endpoints receive 294912 forward/49152 ACK bytes per
active function, interior relayed directions 98304/16384. The queue-specific
maximum is 442368. At MTU 4096 an empty endpoint admits 277504 payload bytes
with the 64 KiB chunk ceiling. This says nothing about physical turnaround.

## Packet and queue assumptions

Linux v6.12 [RXE packet definitions](https://github.com/torvalds/linux/blob/v6.12/drivers/infiniband/sw/rxe/rxe_opcode.c)
give ordinary RC ACK a BTH/AETH and WRITE FIRST/ONLY a BTH/RETH. An IPv4
RoCEv2 ACK frame including FCS is 66 bytes, 70 with one VLAN. Forward
FIRST/ONLY headers total 78/82 bytes before payload and padding. A 128-byte
packet allowance is conservative for this IPv4 format and rounding. The
256-byte forward allowance intentionally retains additional padding.
[rdma-core v54.0](https://github.com/linux-rdma/rdma-core/blob/v54.0/libibverbs/verbs.h)
defines supported verbs MTUs only through 4096; Ethernet MTU 9000 does not
authorize using 9000 in the packet-count calculation. No ACK-coalescing gain
is assumed. RXE describes format, not ConnectX-7 firmware ACK timing.

Linux [mlx5 hairpin setup](https://github.com/torvalds/linux/blob/v6.12/drivers/net/ethernet/mellanox/mlx5/core/en_tc.c)
keys reuse by peer VHCA and priority, not RDMA opcode. Opposite-direction
writes' ACKs are therefore included in each directional envelope. Driver
configuration exposes queue data size and packet count; it does not prove
exact firmware residence or independence of shared physical-port buffers.

Assumptions: ordinary RC traffic without unbounded duplicate retransmissions;
installed reciprocal forwarding matching the topology; independent per-function
and per-direction queues of at least 512 KiB; one plugin process per physical
host in the host network namespace; no unrelated forwarding producers. Queue
count is not a multiplier. All overlapping jobs must use the same topology,
effective budget and wire-version-6 policy, including disjoint communicators.
Peer fingerprints cannot coordinate independent jobs that never connect.

## Connection additions and progress

`connect`/`accept` observes local connections, not a globally closed NCCL
pattern. On a four-host path, an apparent ring may use only origin 3 on queue
1->0, then origin 2 may open a tree/P2P edge to 0 without calling origin 3's
plugin. Revoking origin 3's local cap at that point cannot recall its posted
bytes. No ring-only boost or inactivity borrowing is used. Static allocation
over the complete route set bounds every prefix and every later connection.
If the complete set has only one source per queue, it already gets the full
393216 forward/65536 ACK budget, without inferring an NCCL pattern.

NVIDIA NCCL [connection construction](https://github.com/NVIDIA/nccl/blob/v2.32.3-1/src/graph/connect.cc)
wires rings and trees, while its ext-net interface supplies no global admission
epoch or closed-world certificate. NVIDIA sources are Apache-2.0, copyright
NVIDIA CORPORATION & AFFILIATES. Kernel and rdma-core source retain their
upstream licenses; no external implementation is copied into this plugin.

No sender waits holding only one of the two admission resources. Every split
share can post a control pair, and finite healthy completions return both
balances. A FIFO per relayed function admits the oldest pending request,
independent of which QP supplies a completion. A request keeps its place until
its data and final pair, or its CTS pair, have been posted; it then leaves the
FIFO without waiting for request retirement. Completed WRs immediately return
credit to the shared pool. Each bounded CQ visit refills from that FIFO before
visiting another QP. This avoids repeatedly scanning every waiting request and
prevents newly submitted requests or CQ-list order from bypassing older work.
FIFO links live in request slots and are removed before communicator teardown.
No additional allocation or change to either allowance is required.

Payloads retain adaptive splitting into available credit, including short requests.
No whole-piece admission rule is applied.

CQ visits rotate and shared-window progress visits all QPs, including
submission retries before NCCL owns a request. Each admitted send already has
its peer's CTS; it needs only healthy RC completions to finish posting. A large
request can delay later requests for multiple credit turnovers. Request order
therefore prevents overtaking, but does not guarantee a wall-clock tail or a
bandwidth gain. Direct connections retain their existing progress path. No CUDA or
stream dependency participates. Receiver delivery alone cannot return credit:
it does not prove that ACKs have left all relay queues. Failed or unscheduled
peers are outside the healthy-progress argument.

The independent queue oracle enumerates 2-8 ranks, both directions, reverse
ACKs, paths/cycles/permutations/port flips and three budgets. Provider tests
withhold completions, saturate ACK debt, open later connections, return partial
CQ batches and inject partial control-post failures. Multi-process emulation
checks exact transfers and progress; GPU emulation checks capture/replay. These
checks do not measure physical drops or throughput.
